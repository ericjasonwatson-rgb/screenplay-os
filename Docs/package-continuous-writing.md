# Continuous writing for minimal packages

The experimental minimal-package editor now uses one native NSTextView for the screenplay. Courier text, bold scene headings, paragraph spacing, character/dialogue/parenthetical indents, and right-aligned transitions provide a screenplay-oriented writing surface. This is continuous text, not paginated output or a claim of Final Draft parity. Authored casing and Unicode are not normalized.

Paragraph type follows the caret. Native arrow movement, mouse selection, copying, and selection replacement operate across paragraph boundaries. Return splits at the selection, preserving the first paragraph identity and assigning a new suffix identity. Backspace at a paragraph start removes the boundary and joins its text to the previous paragraph, retaining the previous ID and type. No space is automatically invented at the join. Forward Delete at a boundary and replacements spanning multiple paragraphs use the same transaction. Undo restores all original text, types, order, and identities; Redo restores the same result.

The projection maps UTF-16 native ranges to stable paragraph identities and checks grapheme boundaries. Existing embedded line breaks stay within their original paragraph. Shift-Return and pasted line breaks are text inside the affected paragraph; only ordinary Return explicitly creates a new paragraph. Rendering is deferred during marked-text composition; provisional composition edits enter local recovery without rebuilding the native text storage. Live input-method behavior still needs broader manual coverage.

Every native text-change event commits through PackageTextSession.editSpan. Multi-paragraph deletion/replacement and splitting are atomic history entries. The native event boundary supplies typing Undo granularity; typing coalescing and bounded history storage are future work. The editor retains the existing Add/Delete/type controls, safe-copy writer, and local recovery. No Apply button is necessary in the continuous surface.

The shared command boundary still accepts only the supported two-file minimal profile. Rich packages, anchors, production locks, optional companions, and unknown fields remain protected by the existing editing blockers. Text selection offsets are transient UI state, not canonical document identity. No network, entitlement, or format migration is involved.

Tests exercise native text rendering, Backspace merge, exact Undo/Redo, Unicode insertion, spanning replacement/split, reversed-range rejection, recovered snapshots, save/reopen, and original preservation. Print pagination and a measured long-script optimization are now documented in `package-pagination-performance.md`. Professional screenplay layout conformance remains unclaimed.

Native verification, 2026-09-14: the 740-point-wide sheet displayed the complete screenplay in one text view, with visible scene-heading and dialogue formatting. Down-arrow moved the caret into the next paragraph and updated the type picker. Native backward deletion joined a blank paragraph to its heading; recovery-file inspection confirmed the heading UUID survived and later paragraphs were unchanged. Return created an action paragraph and typing retained focus. Keyboard Undo/Redo and Save Edited Copy succeeded. Disk comparison of Continuous Verified.screenplay confirmed the new action text and UUID, unchanged surviving elements, and unchanged source package. Automated native tests also verify save/reopen and recovery. The full suite passed 105 Swift tests plus 37 Python and 14 self-tests; after adding the native-range regression, the focused 33-test Swift package/preservation suite and the Python/self-tests passed again.

Native edit ranges take precedence over before/after text matching. Repeated newlines can make a text-only diff choose a different boundary with different identity semantics, even when displayed output is identical. The regression test explicitly covers a blank paragraph between two existing paragraphs.
