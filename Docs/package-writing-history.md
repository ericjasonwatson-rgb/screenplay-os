# Package writing history

Undo/Redo now restores the recorded native selection as well as exact screenplay bytes. Selection metadata is tied to a stable history transaction ID and is discarded when its document history entry is removed. It is transient editor state, never package data. Completion, paragraph splitting, selected replacement, and type changes remain independent transactions.

Adjacent single-grapheme insertions within one paragraph form a typing group; adjacent backward deletions form a separate group. A pause of one second, selection movement, a different paragraph or edit direction, clipboard commands, focus loss, save, preview, and Undo/Redo end grouping. Marked-text composition is not grouped by this heuristic. Grouping only affects history: current text and debounced recovery are still updated for every accepted edit.

The preservation session retains at most 200 history steps and 64 MiB of historical document bytes across Undo and Redo. It retains byte snapshots rather than full parsed documents for each step; parsing indexes are reconstructed when a state is restored. Oldest reachable Undo states are evicted first, then furthest Redo states if needed. Current screenplay bytes, the original package, and recovery are not evicted. The byte budget is not a bound on total process memory: current parsing indexes, active buffers, and original source bytes remain additional memory. History is session-local and does not survive reopening.

Tests reproduce and fix completion → Undo → Redo → typing inside the completed word, and per-character undo of continuous typing. Further checks cover grouped backspacing, exact Unicode selection restoration, structural edits, pauses, save boundaries, recovery of the latest grouped edits, 250 history steps, branching after undo, and 70 edits to a one-MiB document. The full suite passed 125 Swift tests, 37 Python tests, and 14 self-tests.

Live verification passed on September 14, 2026. In the packaged app, completing Eli to ELISE, undoing, redoing, and immediately typing X produced ELISEX. Three separate a/b/c keystrokes were undone together; Redo restored them. Three consecutive backward deletions were undone together. A single-character paste had its own Undo step, separate from the preceding typed character. The edited copy saved with No unsaved changes, and disk inspection confirmed the intended text, unchanged surviving IDs, and unchanged source SHA-256. Closing the fixture restored the original legacy workspace.
