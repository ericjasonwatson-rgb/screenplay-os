# Official OTIO validation gate — 2026-11-05

This isolated editorial integration branch brings the experimental read-only
manifest, review, and OTIO JSON export from draft editorial PR #1 onto the
Siri/image branch. It does not include or publish any private screenplay
fixtures from PR #1.

## Provenance and identity

For synthetic fixture data, the exporter retains immutable scene, shot,
board, editorial occurrence, Take, generation-job, output SHA-256 and prompt
SHA-256 fields under OTIO `metadata.screenplayos`. Two edit occurrences
can refer to one generated Take while keeping independent occurrence IDs.
Imported manifest changes to media, order, timing or notes are review
proposals, not application commands. Attempted changes to original Take
identity, generation job or image fingerprints fail validation.

No raw prompt, provider credential or absolute local source path is exported.

## Independent official parser validation

The CI gate uses OpenTimelineIO **0.18.1**, the official Python library,
to parse the OTIO JSON generated by the actual Swift test from a synthetic
two-occurrence fixture, verify metadata and RationalTime values, and
round-trip the timeline through the native `otio_json` adapter.
This checks the native format, not FilmCraft interop or media rendering.

The gate must pass before claiming even official OTIO compatibility.
A separate pinned FilmCraft build and actual import/export remain required
for a FilmCraft compatibility claim. Media paths are deliberately relative
and missing media is represented explicitly; no binary media is sent or
copied in CI.

## Safety and release state

This remains a draft PR stacked on Siri/image PR #8. No creative data
is transferred, no live image generation occurs and no edit is accepted
automatically. Do not merge the integration branch until the parent
branches, license/NOTICE obligations and real NLE interoperability are
reviewed. Public-safe regression testing excludes only 12 tests that
require intentionally private, removed Cat Island source files.

## Official OTIO parser test result

GitHub Actions run #42047172579 passed the macOS editorial/Siri/image
integration gate. The synthetic two-appearance Take timeline, exported by
the actual ScreenplayOS Swift writer, was successfully parsed by the
official `opentimelineio==0.18.1` Python adapter and survived native
OTIO JSON serialization/deserialization with all namespaced identities
and content fingerprints intact. The same run passed the existing
MediaInterchangeManifest, MediaEditReview, MediaTimelineOTIO,
ProductionTakeEditorialBridge, SiriWorkspace and ProductionImage suites.

The first official-parser run failed because the exporter used the
Clip.1 singular `media_reference` field while labeling clips
`Clip.2`. This was fixed to use the Clip.2 keyed
`media_references["DEFAULT_MEDIA"]` and
`active_media_reference_key`. The official parser gate is now mandatory
in the dedicated integration CI workflow.

This result demonstrates native OTIO JSON compatibility for the
synthetic fixture only. It is **not** a FilmCraft import/export
round-trip, and does not verify rate-aware trimming, audio,
multi-track editorial, real media relinking, external API transport,
or an undoable adoption of externally changed edits.

## External editor acceptance — offline review gate

The branch now contains `Scripts/compare_filmcraft_otio.py`, a
fail-closed comparator that accepts a ScreenplayOS-exported OTIO file
and a separately returned OTIO file. Both are parsed with official
OpenTimelineIO, then compared by unique editorial occurrence IDs.
A returned timeline may propose media replacements, time changes,
clip reordering or updated notes. Those changes are printed as
structured, **non-adopted** proposals. An absent/duplicated occurrence,
missing ScreenplayOS namespace, changed Take, shot, board, generation
job, media fingerprint or prompt fingerprint is rejected.

`Scripts/test_filmcraft_roundtrip_review.py` runs synthetic adversarial
cases from the actual Swift OTIO export. The tests never import a
candidate into the ScreenplayOS project or access an AI provider.

`Scripts/run_filmcraft_roundtrip.py` is an optional, intentionally
manual headless FilmCraft invocation. Given a locally verified
`filmcraft-cli` executable, it issues `file.import` and
`file.exportOtio` in one isolated CLI session and compares the
returned OTIO against the original. The wrapper does not download or
trust any latest release automatically. Do not state that the real
FilmCraft round-trip has passed until this command is executed on a
**pinned, checksum-verified** binary and its report is inspected.

Current public FilmCraft documentation describes these command IDs
and a separately distributed macOS CLI. Its rapid release cadence
makes a floating binary unsuitable as an acceptance gate.

## Pinned FilmCraft executable smoke (new CI gate)

The branch now includes a separate macOS workflow, 
`.github/workflows/filmcraft-pinned-roundtrip.yml`, that targets
FilmCraft **v0.17.1** rather than a floating release. It uses the
vendor's published `SHA256SUMS.txt` to check the corresponding macOS
CLI archive before running it. Because the checksum file comes from
the same release host as the archive, this is a basic integrity
check, **not an independently anchored, immutable supply-chain pin**.
A follow-up should record and independently verify the archive digest
before treating the binary as release-certified.

The test exports a synthetic, two-occurrence image timeline through
ScreenplayOS, loads it with the headless
`filmcraft-cli run` command (`file.import` with `replace: true`),
then calls `file.exportOtio` in the same isolated session. Its
returned OTIO is decoded by the official parser and compared against
the original, fail-closed on missing metadata/identity/media paths.
Changed timing, media, ordering and notes are reported as **proposals
only**, never imported into the canonical project.

The workflow has not yet established a pass at the time of authoring
this section. A failed or missing-media import is an interoperability
finding, not permission to remove checks or reconstruct identity.
